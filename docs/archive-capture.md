# Received-content capture and Edit History

Accepted edit updates carry an explicit immutable PurpleArchiveOrigin batch from MessagesController into the queued storage write. Ordinary history/new-message stores carry baseline observations. They never infer an authoritative edit from load_type. The storage hook reads and normalizes the old TL body before upstream replacement or media deletion. Accepted server deletion batches and explicit local deletes pass typed causes; cache-only, scheduled moves and quick replies do not. Secret deletes preserve their accepted chat and random identities before upstream flattens them.

Capture runs on the independent bounded account queue. A storage producer waits at most 250 ms per producer batch, with a 64-message and 8 MiB unit limit and 16 MiB queue reservation. Cancellation releases queued payloads immediately; an active SQLite operation finishes on its owner thread. Failure continues the live update and marks a visible retention gap. An account gap marker is retried into the core gap table; a failed marker remains visibly unacknowledged in memory. There is no cross-database transaction claim.

The encrypted per-message causal journal is keyed by the core HMAC message token. A pending id/order/signature and one account in-flight marker are durable before capture. Startup reconciles that one marker by an exact receipt read, recording a stable interrupted-capture gap on confirmed absence. Exact core receipt reads reconcile interrupted acknowledgement; an affirmative absence plus different input marks an interrupted-capture gap. Accepted stream/pts progress survives local observations and deletions. Disjoint streams refuse instead of comparing unrelated counters. Replay and older pts do not allocate new orders. Local causes share the per-message order. No identities, bodies, raw TL or keys enter diagnostics.

The bridge creates core snapshots and executes PlanArchiveSqlCapture on one closed head/receipt/epoch slice, retaining wrapper metadata and hydrating chunked version bodies. Payloads above 2 MiB raw or the core encoded limit refuse visibly. Known photo/document transport refs, qualities, views and send state do not enter semantic comparison. Unknown TL is retained as explicitly unsupported opaque content. Known typed deletions also preserve malformed cached TL as an opaque preimage. The viewer uses original representation identities and plain read-only text with partial/media warnings, never live MessageObjects.

Each viewer keeps one separate read snapshot, at most eight per account. Pages have at most 32 versions and roughly 2 MiB of text. The full core order cursor is retained. Uncertain reader close retains its store guard and receives at most three close attempts; later account cleanup still drains unresolved readers. Writes, logout, identity changes and explicit discard revoke delivery; refresh starts a new snapshot for the same opening identity. No archive rows enter live history, unread counts, notifications, dialogs or search. Media acquisition, deleted-chat views and purge controls belong to later batches.

Viewer lifetime also captures the opening account selection and selection generation. Each live selector revokes existing viewers, including the Passport chooser that preserves the main fragment. Queued deliveries, Refresh and Older check that lifetime; returning to the previous account cannot revive a revoked model. The activity clears cached pages when it resumes after revocation.
