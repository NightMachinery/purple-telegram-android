# Account settings foundation candidate

This source candidate adapts the accepted shared AccountFiles,
PlanAccountOwnerStartup, ParseLocalChoice and LayerSettings APIs. The predecessor passed the original hook audit, production Java compilation,
changed bridge/shared-unit NDK compilation and genuine prepared host JNI cases.
The complete independent source review required five focused repairs. These
repairs remain unaccepted until affected qualification and focused closure;
application builds and Android observations remain separate.

Root settings, backups, sync store and sync-history retain their legacy paths.
Other identities resolve through accounts/<environment>-<user>/ with Android
history spelling. Resolving and loading never creates an account directory.
The immutable startup owner is independent from the live global account.
Device state, local.toml and accounts/root.toml remain device-wide.

The shared planner selects ownership. Android supplies strict bounded regular
file snapshots, actual production/test metadata and read-only binding evidence.
Unreadable inputs hold operations. Owner writes use copy 2 before copy 1,
expected bytes, private permissions, temporary-file rename, fsync and readback.
The final check is not an operating-system compare-and-swap against an external
editor. Parent-directory fsync and hostile same-UID path substitution are not
claimed. Partial writes retain conservative permissions and recover next start.

Global settings drive Work Mode, lists, filters, Peek and device state.
Last Seen and notification preview use immutable native layered settings
handles keyed by stable identity and account lifetime, never selected-account
fallback. FileObserver watches existing root, accounts, global and signed-in
account directories plus existing ancestors for recreation. Account identity
changes retire caches and pending session ownership. Accountless legacy status
producers remain plain and non-tappable; SelectorUserCell has no proven account
source and remains held rather than guessing the selected account.

This is a partial foundation. Non-root sync, History, Undo, editor writes,
Reset, file creation and version 2 whole-file transfers remain held. Legacy
writes require the root owner and root global role. Manual single-file backup
is available without an owner, but a known non-root destination is refused.
Existing good files are read independently; this candidate does not create or
refresh good files during loading. Promotion after a fully routed account write
is deferred. Root-file correction and UI routing still need focused review;
there is no universal per-account sync or editor acceptance claim.

Settings shows owner recovery, live global choice and fixed role explanations.
It does not implement global-editor/list-fork UX, signed-out account file
creation or binding restoration. Root ownership never follows a live edit.

qualification scope. Copy, Markdown, core and unrelated feature files are
preserved. Gate changes are restricted to file role, reader delegation,
cache invalidation and held editing of the global snapshot.

## Account rows and Reset

account and lifetime. They read its effective layered values and write only its
own settings file through fixed row purposes. Send after save reads that own file
without inheritance. Multiple loaded roles add account, global and file-local

press. Reset delegates to the shared RemoveTableKey and preserves unrelated text.
The broad editor guard remains in place, including app-wide edits whose global
file cannot use the accepted legacy route. No general table writer was unlocked.

An explicit first reasons/trade edit may create the approved minimal version 2
header and requested key. This creation never sends. Missing-file Send after save
is held until a per-account edit has created the file. Existing versions and the
legacy root fingerprint/auto-send policy remain; non-root and version 2 transport
remain held. Existing row-save backup policy is unchanged: the legacy row writer
never took whole-editor/import backups, and these row intents do not overwrite
those backups. Global last-good maintenance remains with the accepted global
reload path. No generic editor, History or transport route was enabled.

Intents retain fragment/activity/account lifetime, owner/global revision and role
epoch, Java/native generations, exact own/global/good/local/owner inputs, regular
file identities and parent directory identities. Synchronous notification precedes
publication and is rechecked; the final fsync-to-rename boundary checks the same
original context under owner/account/settings locks. Reentrant row mutation is
held. Parent creation is exclusive and only owned unpublished temporary files and
empty owned directories may be cleaned. Invalid current own files may display
valid own-good values but cannot be overwritten through these rows. A missing
app-wide file with an existing good copy is held for repair.

The isolated account-row cases invoke actual production JNI and shared splice/
layering code for false pinning, inheritance, Reset, file-local values, minimal
creation, version preservation and invalid-purpose/fallback refusals. Real file
mutation cases exercise the production final-publication helper after fsync and
preparation retirement. These host cases do not execute Android Os, actual
UserConfig/session changes, UI account switching or symlink/directory refusal

### Row-save receipt and debounce repair

Row and legacy saves now share one production debounce coordinator. Every new supported save replaces the pending decision; imports and successful no-send row creations cancel it. A canceled callback is also fenced by entry identity, even if it was already queued. Existing root/schema1, originating account, selected first activated account, file-local flag, imported fingerprint and owner restrictions still run before a send.

The row send receipt retains the original view/account lifetime, owner/global role epoch, exact files and directory identities. Only the actual watcher reload boundary may advance its expected counters: one owner revision and two Java/native invalidations. Both sides require the retained inputs. A changed role, lifetime, path/file or unexpected invalidation permanently retires that receipt. An ordinary own-file refresh therefore preserves the five-second decision without resetting its deadline or recapturing an account.

Final planned text is encoded as UTF-8 and checked against the same 4 MiB reader cap before notification, parent creation or temporary/public file mutation. Oversized output is refused without truncation.

The focused repair fixture invokes the unchanged genuine JNI row plan and the actual production output-byte policy and shared coordinator. Virtual time drives inert decisions, including own refresh, changed context, mixed legacy/row order, canceled queued callbacks and exact-cap/multibyte boundaries. Android Handler/FileObserver dispatch and Os-backed Intent publication remain platform qualification gaps; no host substitute implements those classes. Qualification execution is recorded in the external repair packet.


### Receipt admission before an overdue watcher

The row-save route uses the shared coordinator's admission boundary. On the main looper it registers or cancels immediately, so an already-due400ms watcher cannot run first when synchronous reload/notification work has delayed the UI writer. The five-second decision is scheduled from this admission, without an additional queued hop. Off-thread callers post admission without acquiring the coordinator lock.

Actual row click and Reset callbacks run on the main looper. Legacy arming and watcher refresh also run there, and the application Handler is constructed from that looper. Inline admission therefore runs under the existing owner/files/settings locks on the same thread as watcher refresh; it introduces no concurrent coordinator-to-owner lock inversion. Epoch, role/lifetime/view, exact-file and final send-policy guards remain intact.

The focused admission entry invokes the actual production admission method with a virtual scheduler that leaves an overdue watcher queued while the writer is busy. The queued-policy control loses its otherwise valid decision; inline admission survives the same refresh and preserves the complete five-second delay. Changed context and extra invalidations still retire it, and no-send admission cancels old work. The original39-assertion method is byte-identical and carried without replay. Actual Android Handler/FileObserver dispatch remains a platform gap.


## Android app-wide account chooser

The chooser uses the fragment account and captured signed-in production/test roster. Its row appears with multiple signed-in accounts or a signed-out current source. The signed-out source is labeled explicitly and can be retained as a no-op; it never invents another offline destination. Picker and confirmation retain weak UI references and the original fragment/account lifetime, manager identities, roster and UI/routing generations.

Preview reads the actual current and selected account files, using only that same account's valid recovery copy when the primary is unavailable. Missing primary and recovery inputs preview defaults without creating directories or files. The summary reports actual list/preset counts, schedule configuration, Local Premium, fallback/default/no-app-wide status, paths and the actual missing running preset. Unsupported settings and unreadable/unsafe inputs refuse preview.

The native local-choice splice changes only the global-account scalar and an existing managed path comment. It uses the shared account/path/local-choice/settings parsers, preserves owner, own/follow overrides, unknown Unicode and comments, and verifies strict UTF-8. The production Java model captures readable bytes and physical file/directory identities, rechecks around the final guarded publication, and only cleans its own unpublished temporary inode. It moves no settings/store/History/fingerprint data and sends nothing.

Commit and activation are separate. A detected failed or stale saved commit cannot invoke Normal or Gate activation. A successful missing-preset choice reaches Normal through the real old Gate before loading the selected settings. The model rechecks after Normal, activation and synchronous notification. Saved-but-not-safely-activated results are explicit and never roll back over a foreign writer. State persistence and local choice are not one crash-atomic transaction; the final check-to-rename interval is finite.

The assigned external qualification packet records compiler and genuine model/writer/native causal results. Host callbacks do not instantiate Android Gate/Handler/Os/UI/UserConfig, so physical/native/application/R8/release coverage remains separate. General editors, list forks and version2 transport stay held.

The chooser activation carries the exact validated primary/recovery/default selection into Gate, including recovery flags and the observed-primary watcher fingerprint. Temporary publication uses the production native no-follow, non-truncating open. The actual descriptor must identify the owned regular single-link inode before descriptor chmod/truncate/write/fsync. Pre-open foreign regular and symlink replacements are refused without mutating their bytes or mode. The final publication interval remains finite.

Picker and confirmation use the production dialog-lifetime seam, exact live/showing dialog identity, AlertDialog pre-dismiss retirement and BaseFragment's delegated dismiss callback. Failed shows and dismissed/replaced dialogs revoke queued callbacks; intentional picker-to-confirmation handoff retires only the old picker. Ordinary Gate reloads, including an already queued own local-choice watcher event, freshly apply the same supported primary/same-account recovery/default source policy. They snapshot strict source bytes, physical file/directory identities and the current owner/global/revision/role/settings/native/Gate context before native loading and Java publication. Relevant source/role changes refuse or refresh through a new read; stale recovery bytes are never cached across accounts. Invalid or unreadable source selection retains the previous running resolution rather than silently accepting a future-version primary. General shared parser compatibility and existing watcher/debounce invalidations remain unchanged. Host reload-policy qualification is separate from actual Android Handler/FileObserver/Gate execution.

When fresh source selection refuses malformed/unsupported/unreadable inputs, state progress can still resolve against the last accepted supported bytes for the same owner/global/role/root/resolved file. ### Retained state authority handoff

An ordinary reload that cannot select supported settings derives a use token from
the last accepted source. The token retains the original physical ownership and
owner/global/role context through native resolution, final publication and future
retention. It never captures replacement ownership for the old supported bytes.
Only an accepted fresh supported selection can establish a new authority.
Per-load revision, settings and Gate guards remain separate from that long-lived
authority, so an ordinary watcher refresh can obtain a new load context.

Focused causal cases cover primary and recovery replacement after derivation,
role loss, replacement during and after real native resolution, short-context
loss, fresh supported adoption, and malformed same-inode expiry and End success.
Actual Android static Gate publication, timers, UI, FileObserver and Os dispatch
remain unmeasured; host cases use the production token and original native loader.
Finite check-to-use gaps and cross-file crash atomicity remain unchanged.

### Account-targeted editor candidate

The settings-file block opens the fragment account explicitly, or its distinct
app-wide file, including a signed-out global account. The editor title switches
between those two targets. A dirty switch requires Save, Discard or Cancel.
Opening an absent account file displays the shared account-local version-2
template without creating a file. Save never flattens inherited settings.

Save previews use the shared parser and scope registry. Inactive app-wide keys
are notes grouped by table and key, including app-wide keys within mixed tables.
Warnings remain a separate section. The exact opened bytes, no-follow identity,
parent directories, role inputs, origin lifetime and generations remain bound
through preview, confirmation, backup, publication and notifications. A changed
context after publication is reported as saved with activation unconfirmed; no
rollback or universal filesystem compare-and-swap is claimed.

The first explicit Save can create missing components of this account file's
parent chain. Opening or switching creates nothing. The editor supplies a
narrow creation capability; model callers without it still refuse missing
parents. No setting row is written to create a directory, and no inherited
settings or unrelated key is pinned.

Creation checks the captured parent descriptor, performs an exclusive mkdir,
and retains the created directory's descriptor identity. Before adopting that
receipt, the model rechecks the original account/editor/role token, every disk
input, the parent chain and the exact created inode. An existing name, symlink,
changed parent or changed lifetime refuses further publication. Existing row
creation code is unchanged. Directory creation performs no chmod on existing
paths and never deletes directories. If saving stops after creation, a directory
may remain and the UI says so. File temporary cleanup retains its existing owned
identity check.

These are finite checks around filesystem operations, not a universal atomic
namespace transaction. In particular, mkdir and opening its descriptor are
separate syscalls; concurrent name replacement within an unobserved handoff is
not claimed impossible. No host permission result proves Android behavior.
A missing root file, or a missing primary with its own good copy, remains a
recovery case. App-wide activation remains with the existing guarded watcher.
Editor writes queue no automatic Send, and version-2/non-root transport remains
held. Compiler, genuine JNI/filesystem cases and native UI checks are prepared
but unrun. This candidate does not replace the accepted application.
