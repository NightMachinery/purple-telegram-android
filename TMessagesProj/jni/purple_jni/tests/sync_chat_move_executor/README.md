# Carry executor host suite

Run the registered sync-chat-move-executor configuration through the canonical
B host-suite runner. It consumes actual AGP classes, fresh JNI, core fixtures
and the existing narrow platform/scanner ports. Business-class origins are
asserted against AGP. All peers, messages, files and callbacks are synthetic.
There is no production network backend or UI activation.

The fixture drives the production PurpleSyncChatMove through core NextAction.
Real private files survive reopening, injected durability failures and delayed
transport outcomes. Action and recovery coverage is summarized in
[the move contract](../../../../../docs/sync-chat-move.md).

The matrix pins the four Desktop recovery traps by name:
`deferredDiscardCases` and `precommitDiscard`, `pendingCases` and
`uncertaintyControls`, `ownMarkWinnerRestart`, and `cleanupGone` with
`cleanupControls`. It also covers Switch/Follow/Fill/RepairMark, missing base,
required playlists before delivery, every core action reopening, pending and
own state/stage fault windows, cache union, foreground/observer destruction,
late/duplicate callbacks, throwing cleanup, lock order and actual uploader
constructor claims. `terminalAdmission` opens the ordinary typed N store,
archives a terminal wrapper under a new login, rejects corrupt retained evidence
and preserves no-state Fill admission after later initialization.

The existing discovery/service suite runs `carryQuiescence`, including a held
worker, queued request, reentry and throwing observer. Full host qualification
uses the committed runner and the suite's completion-record floors. Focused
source-cohort probes are diagnostic; final acceptance requires actual AGP classes.

Pending chronology regression: `PurpleSyncChatPendingChronologyCases` reproduces a complete O absence scan captured before an issued send whose ack is lost. Both live Retry and reopen keep ResolvePending and its stage until a new scan; fresh-scan controls reach Plan without deferred work or duplicate sends. `pendingProofs` checks shared-wrapper generation invalidation, single-use absence admission, exact active renewal and post-open scans. The driver reports `PENDING_CHRONOLOGY_CHECKS` separately, with both program/driver floors registered.
