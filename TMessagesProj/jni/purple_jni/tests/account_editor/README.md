# Account editor cases, prepared and unrun

`PurpleAccountEditorCases.run(File)` is prepared for the real production Java
model, real JSON, rebuilt JNI bridge and the accepted consistent host Qt route.
It uses genuine NIO files and the production native descriptor writer and
exclusive temporary creator. It contains no Android classes or policy stubs.
Nothing in this source-only batch has been compiled, imported or executed.

The assertions cover exact text and backup preservation, mixed-table scope notes
from the shared core, global notes suppression, broken/newer/invalid UTF8 input,
strict Java encoding, changed bytes with unchanged length and mtime, retired
context before write, context retirement after publication and before refresh,
synchronous notification retirement, missing-file open without creation,
explicit version-2 first Save, foreign creator, missing-directory refusal and
symlink sentinel preservation. The original missing-directory refusal remains an explicit no-creation-capability
control. New cases use the exact genuine native creation capability supplied by
the editor and require successful first Save for a never-edited account.

Future qualification must compile actual project Java and the changed bridge,
then run this helper with actual class-origin and current input bindings. The
helper has no standalone loader or fake Android runtime. Android-specific
lifecycle, account roster and actual watcher effects require separate native
checks, not a host pass claim.

Prepare these native causal cases using an admitted isolated fixture:

- Open B from B's Purple screen while another account is selected elsewhere.
  The path and title must remain B's. Open app-wide A from that same screen.
  With A signed out, use A's recorded file and label without activating a slot.
- Type unsaved text and switch title target. Cancel preserves text and target.
  Discard changes target only after that explicit choice. Save shows a preview
  of the old target, writes only that target, then opens the requested one.
- Change text or switch targets while background validation or Save parsing is
  outstanding. The old result must not draw, show confirmation or write.
- Dismiss a picker, dirty decision or Save confirmation through the fragment's
  delegated dismissal path, then invoke its retained callback. It must refuse.
- During actual save, have a synchronous notification dismiss the dialog,
  replace the fragment, change text, log out, reuse the account slot, or switch
  global role A to B to A. The retained origin must refuse further work, keep
  new unsaved text, and report any already-published file honestly.
- Change the own file, own good, backup, global input, local choice, owner
  record or ancestor directory after open and after preview. Confirm Save only
  if every retained identity and exact byte input still matches. A foreign
  creator or symlink must remain untouched.
- On a non-global file with mixed `[last_seen]` and `[playlists]` keys, inspect
  the actual Save preview. `trade_remember` and `menu_item_p` are inactive notes;
  per-account `reasons_p` is not. Parser warnings occupy a separate section.
- One-account mode keeps the existing Edit label and ordinary editor title,
  with no title switcher or non-global banner. Error-line cursor navigation,
  multiline entry, Revert and keyboard timing remain available.
- Opening absent own settings creates nothing. In an existing destination
  directory, explicit Save creates only the shared version-2 draft text and
  queues no send. With a missing own directory, only confirmed Save creates it,
  using the retained native receipt, and then writes exactly the shown version-2
  draft. Root-file absence remains recovery, never an inherited-settings copy.
- For a global Save, observe the actual guarded watcher independently. The
  immediate file-save outcome is not proof of app-wide activation. No editor
  Save admits version-2 transport, another account's store, History or Send.


The appended creation cases use real Native Creator calls and real NIO fixtures:

- Missing own directory stays absent through open, then first explicit Save
  succeeds with its created inode/mode receipt and exact template bytes.
- A foreign creator before native mkdir is refused without adoption or removal.
- Replacing the created inode after receipt blocks file publication and keeps
  both the original directory and foreign sentinel.
- A symlink created at the missing name is refused without touching its target.
- Retiring the original context or changing an authority input after directory
  I/O blocks publication, refresh and notification. Owned empty directories may
  remain as a reported partial outcome; no directory rollback is attempted.
- Replacing the parent while copying identical owner-record bytes is refused by
  retained parent identity. Missing owner-record ancestors remain recovery.
- Existing single-account root Save never invokes directory creation.

All predecessor assertions are retained unchanged. Both constructor forms use
the same production model; the old form lacks creation authority, while the
editor and new positive cases supply the actual native creator. These source
cases have NOT RUN. Android lifecycle, actual identity/role generation changes
and permission behavior remain native qualification requirements. The documented
finite check-to-operation gaps are not a universal compare-and-swap guarantee.
