# Sync-chat host cases

Use the canonical `purple/run_host_suites.py` roster. `sync-chat-facts` covers native TL mapping, ownership and eligibility. `sync-chat-io` drives the actual scanner/reader, strict snapshots, upload/post-effect callbacks and record JNI bridge through synthetic ports. It checks typed routes, complete inventories, changed metadata, exact hashes, invalid envelopes and the retained bridge input bound.

`sync-chat-integration` retains typed-ledger, upload lifecycle, runner capability and operation-race cases alongside the modern business classes. Acquisition and release require the exact account key, owner and capability. Publication reads immediate RAM revocation, and stale callbacks cannot release a replacement owner's token.

The modern and automatic suites drive the real account store, History, engine and JNI over private synthetic files. They retain first-use choices, migration, exact-byte conflict heads, uncertainty, retries, account isolation and restart cases. Durable files and retained config bases use `sync_files_bridge.cpp`; record receipts use `sync_record_bridge.cpp`.

Dormant search, mark/setup, move/carry and their controller-specific fixtures are removed. Current Magic and record transport checks remain. All host clocks, deliveries and cloud endpoints are synthetic. These tests make no Telegram requests and do not qualify Android lifecycle, GUI, device filesystems or server behavior.
