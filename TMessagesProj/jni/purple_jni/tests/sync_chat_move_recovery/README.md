# Lost recovery host cases

The canonical driver verifies production-class origins from the current AGP
receipt, loads real JNI and uses real local files. Synthetic ports replace
transport and scheduling. MOVE_RECOVERY_CHECKS is recorded by program and driver
with floors in purple/host_suites.json.

Cases cover removed mark versus ChatGone/unknown reads, exact-state RepairMark,
known reader additions and original baseline, unknown readers/roster and rights,
OFF controls, stale resolve/login/winner/close, repeated Create, protected/gone O
with exact versus absent/mismatched local base, dirty desired text, protected
pending content, Searching cadence and explicit Retry after reconnect.

No device, GUI or Telegram request is made. Host injection does not qualify
real Android lifecycle or server transport. See docs/sync-chat-recovery.md.

The service projection case drives real discovery/service callbacks and the
Searching-to-Lost timers. Only a complete resolution exports R3 MarkGone to the
screen; ChatGone and failed or unknown lookups cannot admit mark repair.
